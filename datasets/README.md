# Physical training traces

Each immutable `vNNN/` directory is one complete collection pass. `v001/` was generated by `scripts/generate_dataset.py` from the fixed ring through Osprey's served PyAT virtual accelerator. That pass used a temporary deck where the four zero-length BPMs were converted from `Marker` to `Monitor`; its test orbit was verified equivalent. The merged checked-in deck now uses `Monitor` directly, and new deployments leave its BPM classes unchanged. The v001 manifest retains its original source and staged-deck hashes. A new run uses a new version directory; the generator refuses to overwrite an existing version.

`attempts.jsonl` has one row per Xopt evaluation. Each row has `episode_id`, `step`, `split`, all 24 PVs in `read_before`, the eight proposed corrector settings and the subset of PVs actually written in `write`, all 24 PVs in `read_after`, objective metrics, and a completion status. Rows with the same episode ID are chronological; train, validation, and test assignments are at the episode level. `episodes.jsonl` stores seeds, initial state, and hidden calibration offsets needed to reproduce disturbances. Hidden offsets are not part of an attempt's model-visible PV observations. `manifest.json` records provenance, run settings, counts, and file checksums.

This is raw machine and optimizer data, not LFM chat training data. A later language pass can append operator prompts and convert selected episodes into Liquid's `messages` and tool-call format without changing the physical observations.

## GPT annotation pass

`scripts/annotate_dataset.py` uses direct [OpenAI Responses API](https://developers.openai.com/api/docs/libraries) calls, with [`gpt-6-luna`](https://developers.openai.com/api/docs/models/gpt-6-luna) as the default. It generates one `operator_prompt` per episode from **only that episode's initial public PV read**, then one retrospective `observation` for each selected read/write/read attempt. The operator prompt is repeated on the episode's annotated rows; it never sees later actions or results. Hidden episode faults are never sent. Prompts get rotating style cues and a BPM-derived factual focus, following the attributed-prompt idea in [AttrPrompt](https://arxiv.org/abs/2306.15895). This resembles Liquid's [robotics demo](https://www.liquid.ai/blog/lfm2-5-230m) in its episode-level language goal followed by tool calls, without claiming their undisclosed data recipe. Both fields permit one or two short sentences. Numeric measurements remain in the copied PV fields, not generated prose; the script rejects unsupported BPM names, numeric claims, omitted prompt focus, or an incorrect orbit-cost trend. Review a pilot for plausible wording and any remaining unsupported qualitative claims before the full pass.

```sh
uv pip install --python .venv/bin/python openai
.venv/bin/python scripts/annotate_dataset.py preview --sample 32
# Set OPENAI_API_KEY in your environment before the paid API calls below.
.venv/bin/python scripts/annotate_dataset.py run --sample 32 --output datasets/v001/annotations/pilot-v4
.venv/bin/python scripts/annotate_dataset.py run --output datasets/v001/annotations/direct-v003
```

The script checkpoints episode prompts in `episode_prompts.jsonl` and step observations in `observations.jsonl`; rerun the **same command** after an interruption to resume missing calls. If the script itself was edited after the run began, add `--resume-after-edit` only after reviewing the new script; the run records both annotator hashes and revalidates saved text. `--sample` selects attempts reproducibly across episodes, but the prompt for each sampled episode still comes from its first attempt. `--limit` selects the first N source attempts. Use a new output directory when changing the annotation schema, model, or selection. `--workers` controls concurrent calls (default 2); actual time depends on API rate limits and latency. After three invalid model observations for one attempt, the script writes a deterministic sentence with the measured cost trend and labels its source `deterministic_fallback`; invalid operator prompts still fail for review. When all selected attempts succeed, `annotated_attempts.jsonl` is written in original episode/step order. Every row is a complete copy of the corresponding physical attempt with an added `annotation` object containing the shared operator prompt, episode prompt ID, per-step observation, and observation source. `annotation_manifest.json` records source and output checksums. The raw `attempts.jsonl` and manifest are not edited. The final model-training conversation conversion is a later step; exploratory actions that worsened cost remain observations and should not be treated as isolated ideal-action examples.
