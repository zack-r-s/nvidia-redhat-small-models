# Mark IV: held-out operator-language evaluation

Mark IV tests the post-Mark-III PR #8 chat interface with 36 one- or two-sentence operator prompts. Three independent agents drafted candidates without reading the repository, training examples, or earlier eval cases. The parent then screened the drafts against v002–v004 training prompts and replaced two plain “center and report” near-paraphrases before freezing [`cases.jsonl`](cases.jsonl). The reproducible [lexical audit](novelty-audit.json) checked all 36 against 2,160 training user turns and found zero exact normalized matches; its similarity ratios are screening aids, not proof of semantic novelty. The suite includes comparisons across BPMs and corrector settings, conditional actions, explicit multi-setpoint writes, unit conversion, unsupported devices, contradictions, and unbounded requests. The prompts and seed IDs are the same for every model and path. This is a narrow test of this 24-PV plant, not an estimate of general accelerator performance.

The [model manifest](models.json) pins five unique checkpoints: base LFM2.5-230M, base LFM2.5-1.2B-Instruct, and hackring v002, v003, and v004. Mark IV does not train or modify any checkpoint. The local path runs each prompt once through the deployed `small_agent` logic over a separate local PyAT fixture, including its explicit-setpoint alias mapping, orbit correction solver, guarded retry, and verified-read fallback. The Gym path presents all four raw tools (`channel_read`, `channel_write`, `channel_limits`, `orbit_correct`) to the model and runs four temperature-0.2 repeats per prompt. Gym provides none of the chat harness's alias map, plane retry, or BPM fallback. A raw-model Gym score and a deployed-harness local score measure different things and must not be subtracted as a model improvement.

Each case resets a fresh `LocalMachine` to its frozen seed with 0.08 mrad disturbance. Conditional expectations are computed from the initial PyAT PVs before the model acts. The deterministic grader checks whether the requested plant action occurred, whether a no-write request stayed unchanged, and whether requested PVs were actually read, including post-write reads where applicable. `success` means both plant and evidence checks pass. The grader does **not** automatically score the prose answer for correct comparisons, unsupported causal claims, invented values, or useful clarification; raw replies and tool traces are retained for that audit. In particular, a no-write case can pass operationally while the explanation is wrong or absent. Local scores include deterministic harness assistance; Gym scores model tool use plus any selected bounded skill computation.

To verify the frozen tasks, run `MPLCONFIGDIR=var/mpl-cache PYTHONPATH=src:scripts .venv/bin/python scripts/prepare_mark_iv.py`. To reproduce a local run, serve a pinned manifest checkpoint with vLLM, start `hackring.api:app` on an isolated loopback port, and run `PYTHONPATH=src:scripts .venv/bin/python scripts/run_mark_iv_local.py --model <served-name> --model-source <source> --model-revision <commit> --model-url <vllm-url>/v1 --fixture-url <fixture-url> --output evals/mark-iv/local/<label>`. To reproduce Gym, set `VLLM_MODEL_NAME`, `VLLM_MODEL_SOURCE`, `VLLM_MODEL_REVISION`, and `VLLM_BASE_URL` for the same served model, then run `scripts/run_gym_mark_iv.sh`. Both runners refuse to overwrite an existing result. Run `PYTHONPATH=src:scripts .venv/bin/python scripts/summarize_mark_iv.py` only after all ten full runs are present; it verifies case hashes, prepared tools, model revisions, and complete rollout counts.

The result index is [`results.json`](results.json). Mark I–III scores remain historical and retain their original task and inference definitions.

| Pinned checkpoint | Local chat, one run (36) | Raw Gym, four repeats (144) |
| --- | ---: | ---: |
| Base 230M | 10 | 11 |
| Base 1.2B Instruct | 14 | 21 |
| v002 | 20 | 14 |
| v003 | 19 | 28 |
| v004 | 11 | 20 |

These are **plant-and-read evidence** successes, not correct-answer rates. Local read-only cases passed for v002 8/12 and v003 7/12; base 1.2B passed 2/12, and base 230M and v004 passed 0/12. On the raw Gym path, every checkpoint passed 0/48 read-only rollouts and 0/48 action rollouts; all Gym successes were on no-write cases. The only local action-case successes were a conditional case whose seeded condition required no write for every checkpoint and one vertical correction by base 1.2B. No checkpoint passed a local exact-setpoint case. Consequently, the apparent local lead of v002/v003 is confined chiefly to fetching the right PVs; it does not establish reliable execution of unfamiliar natural-language control requests.

Trace inspection shows concrete failures that aggregate scores hide. On a corrector-setting request, base 230M reported BPM positions as kick settings. On a 250-microradian H02 request, it read a BPM and described a position in mm as though it were the H02 setting. Some v002 runs fetched the requested PVs but ended at the five-step limit without a reply. Base models also made writes in Gym that did not satisfy the requested action; the trained checkpoints made no accepted Gym writes in this suite. These observations are trace-specific, and the current grader intentionally does not certify the factual quality of generated prose.
