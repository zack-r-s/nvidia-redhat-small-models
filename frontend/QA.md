# Viewer QA notes

Fixture checks on 2026-10-17 used headless Chromium (Playwright, SwiftShader WebGL) against the local PyAT API (`hackring.state/1`). A later live check used the served Osprey/PyAT accelerator through EPICS.

- **Readings vs `/state`:** `scripts/qa_state_match.py` loads the viewer at 1440×900 and 390×844 and compares all 24 PV values rendered in the DOM (`data-testid="pv-<PV name>"`) to `GET /state` (tolerance 5e-5 display rounding): 0 mismatches. No horizontal overflow at either width.
- **Live:** status tag "Live (fixture)", source label says local PyAT fixture, not live Osprey.
- **Stale / disconnected:** API killed while open → "Stale" with dimmed readings after ~2 s (last sample age shown), "Disconnected" after ~8 s; fresh load with API down → "Disconnected", no data, no fabricated values.
- **Replay:** `/?replay=/replay/demo.json` plays 20 recorded, unmodified `/state` frames from a seeded (7) Xopt Nelder–Mead run; badge "Replay", run ID, seed and frame counter visible; no interpolation.
- **Unavailable by design:** agent intent, Osprey action status, target/goal show an explicit unavailable state (no backend contract).
- **Read-only:** outside `TestDriver.tsx` (dev-only, `?driver=1`), `/write` and `/scenario` appear nowhere in `frontend/src`, and `frontend/dist` contains neither. The viewer itself only issues `GET /state`.
- **Test driver:** 7 presets applied via the drop-down, rendered values matched `/state` each time (0 mismatches); the out-of-limit preset returned 422 and left `/state` unchanged; the panel is absent without `?driver=1`.
- Still not covered: device click-inspection (manual), real-GPU WebGL rendering.

- **Live beam view:** per-BPM transverse x–y spot panels (shared scale, reference crosshair; latest dot plus the last 8 samples as unjoined faint dots, `SPOT_DOTS` in `BeamView.tsx`) and an RMS-vs-time strip. Connecting lines between 0.5 s *measured* samples remain absent because they imply an unmeasured path. The 3D scene maps measured deviation into the translucent tube: its cross-section is a selectable display window (±0.5/1/2/5 mm, default ±2), with the equivalent magnification printed in the legend. Dots beyond the window are clamped to the tube wall and turn yellow; the tube is not the physical pipe. Tables stay in true units. The separate green moving marker and fading trail follow an additive `orbit_profile` computed from the full local PyAT lattice, sampled in memory at no more than 0.2 m intervals. The five-step slider changes display playback only; Max holds a line through the model samples. An unchanged profile does not restart on each `/state` poll, and stale feeds freeze the cursor. Osprey/EPICS and older replay files without the profile continue to show BPM dots without a modeled path. Three interpolates only for drawing; it does not add PVs or physical dynamics.

- **Poll ordering (PR #1 review):** `/state` is now polled serially (next request scheduled after the previous settles, in-flight request aborted on unmount) with a sequence guard. `scripts/qa_poll_order.py` delays replies in the browser (slow first, then fast) and checks that at most one request is in flight and the displayed snapshot never goes backwards: old code showed 3–4 backwards steps and 2 in flight, new code 0 and 1.

## Live Osprey check

On 2026-10-17, `scripts/qa_state_match.py --chrome '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'` compared all 24 displayed PVs with the Osprey-backed `/state` endpoint at both 1440×900 and 390×844. Both showed `Live (Osprey)`, zero PV mismatches, and no horizontal overflow. A separate read-only check found all 24 `/state` PVs equal to their EPICS values. With H01 at 0.124 mrad, its setpoint and readback agreed, and all eight BPM coordinates matched an independent PyAT calculation for that kick. This verifies the shared backend and displayed numbers at that observed state; it does not establish a continuous orbit curve or test the future target/agent-event panels.

- **Chat-UI layout (wrs-chat-ui):** viewport-height workspace with no page scroll at 1280×720, 1440×900 and 1920×1080: slim top bar; ring schematic on the left; right column with a tabbed insight panel (Beam = beam spots over orbit RMS history, Readings, Correctors, Agent & goal) over the chat panel; test driver as a popover. Mobile stacks without horizontal overflow (tab strip scrolls). `scripts/qa_state_match.py` crops snapshots to the central `.workspace` and still matches all 24 PVs at desktop and mobile widths; `qa_poll_order.py` still passes. Chat checked against the dev bridge in live mode (reads, confirmed write, guard-rejected write with tool traces) and scripted mode via pytest.
- **Beam tab:** beam spots and RMS history share one tab with separate bold labels ("Beam spot" with its mm scale, "Orbit RMS" with its sample count and range). Verified during an Xopt run: the RMS polylines carry 22 samples with 12–13 distinct values and the spot dots converge toward the crosshair; at 1440×900 it needs no inner scroll, at 1280×720 the pane scrolls slightly (320 vs 286 px) with no page scroll.

## Mark III shared-fixture check

On 2026-10-18 the fixture-first live path used v004, the local PyAT API on 8001, the chat bridge on 8002, and the viewer on 5173. The four-case [smoke record](../evals/mark-iii/live-fixture-v004.json) passed read-only BPM reporting, exact numeric H01 write plus measured post-write BPM, model-selected `orbit_correct` with lower measured X/Y RMS, and an out-of-limit refusal with unchanged PVs. Exact numeric writes are explicitly labeled as a bounded harness action; that case does not measure v004 numeric tool selection. `POST /chat/reset` returned the same seeded disturbance, and the chat's Agent & goal panel uses the reported measured before/after state. This record predates the optional modeled green path; its beam-position and PV claims remain about measured data.

The Mark III browser check compared all 24 rendered PVs to `/state` at desktop and mobile sizes with zero mismatches or horizontal overflow. The polling-order check saw at most one in-flight request and zero backwards display steps. Replay hides the live chat and test driver. These historical checks also predate the green path; the new marker is a closed-orbit playback cursor, not tracked particle motion.

The green-path check on 2026-10-18 repeated desktop and mobile `/state` comparisons after the additive profile: all 24 PVs matched, with no horizontal overflow. The polling-order check saw 13 requests, at most one in flight, and zero backwards steps. A temporary seed-7, 0.15 mrad disturbance gave a 2.7746 mm horizontal span in the PyAT profile and a visibly displaced green path at Max playback; the fixture was restored to nominal afterward. Python fixture tests compare the dense profile to all four BPMs and confirm deterministic snapshots and EPICS omission.

`scripts/qa_shared_fixture_ui.py --chrome /path/to/Chrome` also drove the actual browser chat: an exact H01 request produced a confirmed Agent & goal panel, a 0.1 mrad setpoint in both `/state` and the displayed PV cell, and a reset that restored H01 to zero and cleared the panel.
